# 前端重设计：审查与设计方案

> 范围：`frontend/`（SvelteKit 管理台）。**所有功能、接口调用、数据流保持不变**，只改布局、视觉与交互呈现。
> 依据：通读 `app.css` / `+page.svelte` / 全部 22 个组件源码，并在本地拉起网关实测截图（登录、用量总览、模型、用户、权限组）。

---

## 第一部分：现状审查

### 总评

功能完整、信息架构合理，但视觉语言停留在"2019 年开源后台"：灰底白卡堆叠 + 钢蓝色按钮，没有品牌识别、没有数据性格、没有层级节奏。核心问题不是"不够花哨"，而是**每个页面都是同样的"表单面板 + 表格面板"纵向堆叠**，创建、筛选、浏览、操作四件事挤在一屏里互相争夺注意力。

### 5. 感知性能与可访问性

- `refreshAll` 一次拉全量 inventory（当前库里 10,373 个 subject），列表首屏空置数秒且无骨架，看起来像坏了。
- `--text-soft: #7b8493` 在白底上对比度约 4.0:1，小字号下不达 AA。
- 响应式只有 900px 一个断点，表格在窄屏靠横向滚动；焦点可见性依赖浏览器默认。
- 无 ARIA loading/empty 语义标注。

### 6. 代码组织（制约设计迭代的部分）

- `+page.svelte` 1,757 行单文件承载 14 个 section 的状态与视图；`OwnedDashboard` 40 个 props 传递。改样式可行，但**换布局结构**前需要先把每页拆成独立组件（这属于重构不改功能）。
- 全局类名（`.panel/.grid/.form-grid`）语义过载，`.grid` 同时用于指标卡和表单。

## 第二部分：设计方案 —— 「调度台」Dispatch Console

### 概念定位

这个产品是**模型流量的调度台**：下游是 Codex / Claude Code / OpenAI 客户端，上游是推理端点，中间是路由、配额、限流、审计。它的一切数据都是"流"：token 流、请求流、时间窗配额。设计就该长成这个样子——

- **性格**：冷静、精密、可信赖的仪表台。不炫技，数据是主角。
- **受众**：企业内部平台管理员（重数据密度）+ 普通开发者（只看自己的密钥和用量）。
- **一个记忆点（signature）**：**流量带（Traffic Ribbon）**——一条贯穿产品的水平时间序列条带，用量总览页是它的全尺寸形态（按模型堆叠的 token 柱），KPI 卡里是它的迷你形态（sparkline），权限组配额是它的仪表形态（三时间窗余量条）。同一视觉基因三种尺寸。
- **一个克制的冒险**：**数据用等宽字体说话**。全站所有数字（token、RPM、并发、ID、时间戳）切到 mono + `tabular-nums`，中文界面与等宽数字混排，形成"仪器感"。这是本方案唯一激进的排版决定，其余一切保持安静。

**双声部配色**：结构色（钴蓝，负责导航/按钮/链接）与数据色（青绿 flow，负责一切"流量/用量"呈现）分离。看到青绿即知是数据，看到钴蓝即知是操作。

### 设计原则

1. 每页只有**一个主角**：列表页主角是表格，创建收进抽屉；总览页主角是流量带。
2. 操作密度与使用频率成正比：行内只留 1 个高频开关，其余进 `⋯` 菜单。
3. 数据可视化优先于数字罗列：能画趋势的不堆卡片。
4. 无网络依赖：全部系统字体 + 纯 CSS/SVG 图形，不引第三方图表库，适配企业内网。

### 1. 设计令牌（Design Tokens）

替换 `app.css` 现有 `:root`，类名可全部保留：

  --surface:     #FFFFFF;   /* 卡片/表格 */
  --surface-sunk:#EEF1F6;   /* 表头、输入底、次级块 */
  --rail:        #111826;   /* 指令栏（深墨蓝） */
  --rail-line:   #232D40;
  --rail-ink:    #E7ECF5;

- 表头：11px、600、`letter-spacing: .08em`、**去灰底**（只留 hairline + `--ink-500`），告别 2010 感。

- **指令栏（rail）**：`--rail` 底色。顶部品牌区：网关字形 logo（两个穿过方括号的 chevron，纯 SVG）+ 产品名 + 环境芯片（`local` 小圆点胶囊，颜色映射环境：local 灰 / staging 琥珀 / prod 红——读 `diagnostics.environment`，功能不变）。导航：**图标在左**，激活项 = 3px 圆角 accent 指示条 + `rgba(46,91,230,.16)` 底 + 文字变白；分组标题 11px tracked caps。底部：用户卡（首字母圆形头像 + 姓名 + 工号），退出收纳进用户卡 hover 菜单。

### 3. 组件规范

**Button**（36px 高 / icon 32px，radius `--radius-m`）
- primary：`--accent` 实底白字，hover `--accent-strong`；secondary：白底 `--line-strong` 边；ghost：无边透明，hover `--surface-sunk`；danger：`--danger` 实底，仅用于删除确认等终态操作。
- 统一 `:focus-visible { box-shadow: var(--ring) }`；加载态 = 左侧 14px spinner 图标（文字不变）。
- 高危操作（删除）一律二次确认弹层，不再用 `confirm()`。

**Input / Select / Checkbox**
- 36px、白底、`--line-strong` 边、radius `--radius-m`；focus：边框 `--accent` + `--ring`。
- select 自绘 chevron；搜索输入带左侧放大镜图标和 `⌘K` 预留位。
- 数字输入右对齐 mono。

**Badge**：去边框。`圆点 + 文字 + soft 底`（如 `● 启用`），radius `--radius-s`，12px。语义：ok/warn/danger/neutral/flow 五档。空值统一 `—`（替换"缺失"）。

**Table**（核心资产）
- 行高 44px、13px、`th` 无底色 11px caps；斑马纹关闭，hover `#F8FAFC`。
- `nowrap` 只作用于数字/ID/徽章列；名称/备注列 `text-overflow: ellipsis` + `title`。
- **操作列**：行内最多 1 个开关按钮（启用/禁用 toggle）+ `⋯` kebab 菜单（编辑×N / 删除（红））。菜单项 = 原有全部按钮，功能一一对应。
- 行点击 → 右侧详情抽屉（实体概要 + 全部字段 + 该实体的操作）。
- 表格底：左侧 `显示 1–30 / 共 10,373`，右侧数字分页（`‹ 1 2 … 345 346 ›` + 每页条数选择 30/50/100）。
- 加载：表头下 3 行 shimmer 骨架；空：EmptyState。

**EmptyState**：居中 40px 线性图形（沿用 lucide 图标描边风格）+ 一句指引 + 一个行动按钮。例："还没有模型别名 → 创建第一个模型别名"。

**Drawer（抽屉，420px）**：右侧滑入，用于创建/编辑表单与实体详情。两列字段网格、粘性页脚（取消 / 保存）。替换全部 `prompt()` 与置顶创建面板。

**Modal（640px）**：仅保留给"签发密钥成功展示明文"、"CIDR 编辑"等需要强关注的场景；`--shadow-pop` + 遮罩 `rgba(13,21,36,.45)` + focus trap。

**Toast**：右上角堆叠，4s 自动消失；success（ok）/error（danger）两档。替换 `pageError` 红条与"操作成功无反馈"。

**Tabs / Segmented**：时间范围快捷选择（1h/1d/1w/1M）改为 segmented control，选中项 `--surface` 底 + `--ink-900` 字 + 边框，替代 4 个平级按钮。

**CommandBlock / CopyValue**：`--ink-900` 底 + flow 青绿的 `$` 提示符；复制按钮成功后变 `✓ 已复制` 1.5s。所有可复制值 mono。

**流量带 TrafficRibbon（signature 组件）**
- 数据源：现有 `analyticsBuckets`（`bucket_start` + `total_tokens`，维度=模型时按模型堆叠；否则按 outcome 着色，成功=flow、失败=danger）。
- 实现：纯 CSS flex 柱（每桶一柱，`flex:1`，高度 = tokens/max），无第三方库；容器高 96px，底部时间轴刻度 11px mono；hover 单柱浮出读数（时间 · 模型 · tokens · 请求）。
- 迷你形态（sparkline，高 28px）用于 KPI 卡背景趋势。
- 首次载入柱条从 20% 高度升起（180ms，`prefers-reduced-motion` 时禁用）。

**配额仪表 QuotaChips**（权限组表格行内）
```
┌──────────────────────────────────────────────┐
│  早 ▓▓▓▓▓▓▓░░░ 3.4M/5M   午 ▓▓░░░ 0.8M/5M ←当前(高亮描边)  晚 ∞ │
└──────────────────────────────────────────────┘
```
- 每窗一条 6px 进度条（used/limit，mono 数字），当前时间窗整 chip 描边 `--flow` + 浅底；无限量显示 `∞`。
- 用量 ≥ 80% 转 `--warn`、≥ 100% 转 `--danger`（数据已有：`_attach_usage`）。

**KPI 卡**
- 结构：小标签（11px）+ mono 大数字（26px，`fmtNumber`）+ 右侧 28px sparkline + 底部与上一等长周期的环比（`▲ 12.4%` flow / `▼ 3.1%` ink-500）。
- 请求数 / 总 token / 成功率 / 平均延迟 四张为主；资源概览（用户/项目/密钥/模型计数）降级为次级一行 chip，不再占 4 张大卡。

### 4. 逐页布局

### 5. 交互升级映射表（功能不变）

| 现状 | 新方案 | 功能等价性 |
|------|--------|-----------|
| `prompt('备注')` 编辑 | Drawer 表单字段 | 同一 PATCH 端点 |
| `confirm()` 删除 | Modal 二次确认（红色主按钮 + 输入名称确认可选） | 同一 DELETE 端点 |
| 置顶创建面板 | `+ 新建` → Drawer | 同一 POST 端点 |
| 行内 6 按钮 | toggle + kebab 菜单 | 全部动作保留 |
| 按钮文字置换加载 | spinner + 全局进度线 | 状态不变 |
| pageError 红条 | Toast + 字段级 inline error | 提示不变 |
| 4 个时间快捷按钮 | segmented control | 同一 setUsageRange |
| 上一页/下一页 | 数字分页 + 每页条数 | 同一前端分页逻辑（pageRows） |

### 6. 动效规范

- 页面切换：内容区 12ms 内 fade + 4px 上浮，180ms ease-out。
- 抽屉：260ms `cubic-bezier(.2,.8,.2,1)`；遮罩 fade 180ms。
- hover 反馈统一 `--dur-fast`。
- 流量带载入升起动画。
- 全部动效包在 `@media (prefers-reduced-motion: no-preference)` 内。

### 7. 文案规范

- 空状态给下一步：「还没有 X → 去 creating」。
- 加载统一「加载中…」；按钮保持动词原形（保存/创建/查询），不再置换为"查询中"。
- 状态词表：启用/停用（弃"禁用"歧义可保留）、成功/失败、就绪/未就绪、空值 `—`。
- 破坏性操作明确后果：「删除用户 l00014624——该操作不可撤销，其密钥将立即失效」。

### 8. 可访问性底线

- 全交互元素 `:focus-visible` ring；对比度：正文 ≥4.5:1（`--ink-500` 起步）。
- 骨架/加载/空态带 `aria-busy`/`role="status"`。
- 表格操作菜单键盘可达（Enter 展开、Esc 关闭、方向键移动）。
